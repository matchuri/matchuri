# 레이어드 아키텍처 복귀 결정

## 상태

2026-11-06 채택. 현재 백엔드는 단일 Gradle 모듈의 레이어드 구조를 사용합니다.

## 배경

Spring Modulith와 8개 Gradle 모듈을 도입해 도메인 책임과 의존성을 명시했습니다. 그러나 도메인 책임 분리가 아직 성숙하지 않아 공개 인터페이스, 이벤트, 모듈별 빌드 설정을 유지하는 비용이 현재 개발 규모에서 얻는 이점보다 커졌습니다.

## 결정

- 기존 `src/main/java/matchuri/backend/{api,domain,global,infra}` 패키지 구조로 복귀합니다.
- Modulith 의존성, 모듈 선언, 하위 Gradle 프로젝트와 모듈 전용 경계 검증을 제거합니다. 별도 패키지 재설계는 하지 않습니다.
- 공유 이력은 유지하며 모듈 경계 리팩터링과 Modulith 도입을 역순으로 revert합니다.
- 도입 전의 `RollbackRecordExecutor`와 도입 이후 회원 탈퇴 시 그룹 추천 정리, 개인 추천 점수 기준, 시드·커버리지 검사·대표 통합 테스트, 의존성 버전과 실행 설정 개선을 보존합니다.
- 도입 커밋에 포함됐던 SSE 수신자 재검증·유효한 초대 확인·연결 정리와 해당 회귀 테스트도 보존합니다. 이 기능은 레이어드 패키지의 저장소 의존으로 구현하며 모듈 전용 인터페이스는 복원하지 않습니다.
- API·JPA 감사에서 검사 대상이 비었을 때 실패하는 보호 조건과 테스트용 DB 분리도 유지합니다.
- API 경로와 요청·응답 계약, 데이터 정책은 구조 복귀로 변경하지 않습니다.

따라서 복귀 결과와 도입 전 기준 커밋 `0f6a966`의 차이에는 보존 대상 개선과 위 SSE 보호 동작이 포함됩니다. 과거 소스 전체를 그대로 복원하는 작업으로 보지 않습니다.

## 결과와 재검토 기준

서비스 트랜잭션과 도메인별 패키지 책임을 기준으로 개발합니다. 현재 구조와 구현 위치는 [아키텍처](../backend/architecture.md)와 [백엔드 가이드](../backend/guide.md)를 따릅니다.

도메인 책임과 변경 이유가 안정되고 실제 순환 의존성·협업 비용이 확인되면 패키지 의존 규칙이나 모듈 분리를 다시 검토합니다. 이번 결정에서는 새 경계 도구나 추가 추상화를 도입하지 않습니다.
