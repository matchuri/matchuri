# 추천 점수 계약

이 문서는 개인·비회원·그룹 추천의 점수 의미와 계산 정책을 설명합니다. 실제 계산은 백엔드의 `RecommendationPreferenceMatchCalculator`, `SingleParticipantMenuRecommendationAlgorithm`, `GroupMenuRecommendationAlgorithmV1`을 기준으로 봅니다. HTTP 필드와 예시는 OpenAPI 메타데이터와 `/docs/openapi` 산출물을 기준으로 봅니다.

## 점수의 의미와 적용 시점

- 후보의 `score`는 0~100으로 정규화하고 소수 첫째 자리로 반올림한 추천 지표입니다. 만족 확률, 찬성 인원 비율, 최종 투표 결과를 뜻하지 않습니다.
- 개인은 한 사람의 취향과 선택 이력, 그룹은 구성원별 취향 일치율과 비선호 감점을 사용합니다. 서로 다른 추천 종류의 점수를 동일한 척도로 비교하지 않습니다.
- `rankNo`는 원점수 내림차순으로 정하며 동점이면 메뉴 ID 오름차순입니다. API에 원점수와 계산 내역을 노출하지 않습니다.
- 알고리즘 메타 버전 `v1`은 선호 속성 ID를 각각 계산합니다. `v1.1`은 음식 분류와 온도감에 OR 규칙을 적용합니다. 회원 개인 추천은 `v1.2`에서 모든 카테고리 유형에 OR 규칙을 적용하며, 비회원·그룹 추천은 `v1.1`을 유지합니다. 클래스 이름의 `V1`과 API 경로의 `v1`은 메타 버전과 별개입니다.
- 새 규칙은 새로 생성하는 후보에 적용합니다. 이미 저장된 개인·그룹 후보와 이력 점수는 재계산하거나 덮어쓰지 않습니다. 회원 후보 메타의 `algorithmVersion`, `scoreBreakdown`으로 생성 당시 계산을 구분합니다. 비회원 추천은 결과를 저장하지 않습니다.

## 선호 평가 단위

구성원별로 분모인 선호 평가 단위 수 `U`와 분자인 일치 평가 단위 수 `M`을 계산합니다.

| 카테고리 유형 | 회원 개인 `v1.2` | 비회원·그룹 `v1.1` |
| --- | --- | --- |
| `FOOD_CATEGORY`, `TEMPERATURE` | 선택한 유형마다 1단위. 그 유형에서 선택한 속성 ID 중 하나 이상이 메뉴와 일치하면 충족 | 회원 개인과 동일 |
| `FLAVOR`, `COOKING_METHOD`, `TEXTURE` | 선택한 유형마다 1단위. 그 유형에서 선택한 속성 ID 중 하나 이상이 메뉴와 일치하면 충족 | 선택한 속성 ID마다 1단위. 각 선택 ID가 메뉴와 일치하면 충족 |

- 회원 개인 `v1.2`는 모든 `CategoryType`에 같은 OR 규칙을 적용합니다. 같은 유형에서 여러 항목을 선택하면 가능한 대안으로 평가하며, 유형 간에는 각각 독립적으로 계산합니다.
- 같은 유형이라는 이유만으로 일치하지 않습니다. 선택한 속성 ID와 실제로 일치해야 합니다. 예를 들어 매콤·진한 맛 선호에 단맛만 가진 메뉴는 맛 유형이 불일치합니다.
- OR로 계산하는 유형은 선택한 속성 ID가 여러 개 일치해도 해당 유형이 최대 1단위만 일치합니다. 선택하지 않은 유형과 메뉴의 추가 속성은 취향 일치 계산에서 가점·감점이나 분모 증가에 사용하지 않습니다.
- 선호가 없으면 `U=0`이며 취향 점수는 0입니다. `U>0`이면 일치율은 `M/U`입니다.
- 실제 API 유스케이스는 저장된 카테고리의 유형 정보를 알고리즘 입력에 전달합니다. 유형 정보가 없는 내부 입력은 알 수 없는 ID를 개별 단위로 계산하며, 기존 ID 기반 테스트 입력을 유지합니다.
- 후보 메타의 `categoryMatchingCount`와 그룹의 `preferenceMatchingCount`는 해당 알고리즘 버전에서 일치한 평가 단위 수입니다. 그룹 값은 구성원별 일치 단위 수의 합계입니다.

### Before / After

아래는 선택 이력이 없고 비선호 감점도 없으며, 모든 선택 ID의 유형 정보가 있는 예입니다. 그룹은 모든 구성원의 선호가 같은 경우입니다.

| 선호 | 메뉴 속성 | `v1` | 비회원·그룹 `v1.1` | 회원 개인 `v1.2` |
| --- | --- | ---: | ---: | ---: |
| 한식·중식, 뜨거움·차가움 | 한식, 뜨거움 | 2/4 → 50점 | 2/2 → 100점 | 2/2 → 100점 |
| 한식·중식, 뜨거움·차가움, 매콤·진한 맛 | 한식, 뜨거움, 매콤·진한 맛 | 4/6 → 66.7점 | 4/4 → 100점 | 3/3 → 100점 |
| 매콤·진한 맛, 국물·구이, 바삭·쫄깃 | 매콤, 국물, 바삭 | 3/6 → 50점 | 3/6 → 50점 | 3/3 → 100점 |
| 매콤·진한 맛, 국물·구이, 바삭·쫄깃 | 단맛, 국물, 바삭 | 2/6 → 33.3점 | 2/6 → 33.3점 | 2/3 → 66.7점 |
| 한식·중식, 뜨거움·차가움 | 일식, 차가움 | 1/4 → 25점 | 1/2 → 50점 | 1/2 → 50점 |

### 기존 `v1`·`v1.1` 그룹 점수 비교

백엔드의 `RecommendationScoreComparisonIntegrationTest`를 각 브랜치에서 IDE로 직접 실행합니다. 콘솔에 그룹 점수 3줄을 출력하는 비교용 테스트이며, 전용 Gradle task는 없습니다. 명령줄에서는 기존 `test` task로 실행하고 점수 행만 표시할 수 있습니다.

```powershell
git switch chore/recommendation-preference-baseline
.\gradlew.bat test --tests '*RecommendationScoreComparisonIntegrationTest' --info --rerun | Select-String 'SCORE_COMPARISON'

git switch fix/exclusive-recommendation-preferences
.\gradlew.bat test --tests '*RecommendationScoreComparisonIntegrationTest' --info --rerun | Select-String 'SCORE_COMPARISON'
```

두 브랜치의 테스트 코드는 동일합니다. 같은 메뉴 1개와 동일 취향의 그룹원 3명을 사용하고, 선택 이력·제한 재료·비선호 없이 해당 브랜치의 실제 그룹 후보 생성 경로를 호출합니다. 메뉴 속성은 한식·뜨거움·매콤·진한 맛·국물·바삭입니다.

| 출력 조건 | 선호 | `v1` → `v1.1` |
| --- | --- | ---: |
| `EXCLUSIVE` | 한식·중식, 뜨거움·차가움 | 50.0 → 100.0 |
| `MIXED` | 위 선호 + 매콤·진한 맛 | 66.7 → 100.0 |
| `OTHER_TYPES` | 매콤·진한 맛, 국물·구이, 바삭·쫄깃 | 66.7 → 66.7 |

출력은 반환받은 실제 점수이며 기대 점수를 고정하지 않습니다. 병합 후에는 새 로직의 점수가 출력되므로 Before를 다시 보려면 변경 전 PR 브랜치에서 실행합니다.

## 개인과 비회원 추천

- 제한 재료가 포함된 메뉴, 비선호 메뉴, 입력으로 전달된 최근 선택 메뉴와 최근 SKIP 메뉴를 제외합니다.
- 취향 점수 `C`는 `U>0`일 때 `50 × M/U`, 아니면 0입니다.
- 회원 선택 이력의 속성별 선택 빈도를 `f`, 메뉴 속성에 해당하는 빈도 합을 `h`라고 할 때, 정렬용 이력 점수는 `50 × h / max(f)`입니다. 이력이 없으면 0입니다.
- 원점수는 `C + 정렬용 이력 점수`입니다. 응답 정규화에 쓰는 이력 점수는 `50 × h / sum(f)`입니다. 정렬용 이력 점수와 정규화용 이력 점수의 분모는 서로 다릅니다.
- 응답 정규화의 최대 가능 점수는 선호가 있으면 50점, 선택 이력이 있으면 50점을 더해 계산합니다. 응답 점수는 `100 × (C + 정규화용 이력 점수) / 최대 가능 점수`를 0~100으로 제한해 반올림합니다. 최대 가능 점수가 0이면 응답 점수도 0입니다.
- 비회원은 선택 이력 입력이 없으므로 선호가 있을 때 응답 점수는 `100 × M/U`입니다. 회원도 선택 이력이 없으면 같은 계산을 사용하지만, `M`과 `U`의 평가 단위는 위 표처럼 추천 종류별로 다릅니다.
- 회원 개인 `v1.2`는 선호가 있고 선택 이력이 없을 때 모든 선택 유형을 충족하면 응답 점수가 100점입니다. 선호와 선택 이력이 모두 없으면 0점입니다. 유형 정보를 알 수 없는 내부 입력의 ID는 개별 단위 충족도 함께 계산합니다.
- 이번 OR 확대는 회원 개인의 취향 점수에만 적용합니다. 선택 이력의 속성별 빈도 계산과 결합 방식, 정렬용 원점수 계산은 기존 방식을 유지합니다. 선택 이력이 있으면 모든 선택 유형을 충족해도 최종 응답 점수 100점을 보장하지 않습니다. 원점수 정렬과 응답 점수 순서가 다를 수도 있으며, 이력 결합과 순위 계산 통일은 별도 후속 과제입니다.

## 그룹 추천

- 후보 생성 당시 활성 그룹원의 제한 재료를 합집합으로 모아 해당 재료가 포함된 메뉴를 제외합니다. 최근 SKIP 메뉴도 제외합니다.
- 비선호 메뉴는 개인과 달리 제외하지 않고 감점합니다. 그룹의 선택 이력과 최근 확정 메뉴는 현재 점수 입력에 사용하지 않습니다.
- 선호가 있는 구성원 수를 `P`, 후보를 비선호로 지정한 구성원 수를 `D`라고 하면 원점수는 `50 × 구성원별 일치율 합계 − 25 × D`입니다. 선호가 없는 구성원도 비선호 지정에 따른 감점에는 포함됩니다.
- 최대 가능 점수는 `50 × P`입니다. `P>0`일 때 응답 점수는 `100 × 일치율 합계 / P − 50 × D / P`를 0~100으로 제한해 반올림합니다. `P=0`이면 0점입니다.
- 비선호 감점이 없고 동일 취향의 구성원이 늘어나면 응답 점수는 유지됩니다. 서로 다른 취향을 평균내므로 개인 최고 점수보다 그룹 최고 점수가 낮을 수 있습니다.
- 평균만 사용하므로 구성원별 일치율 `[100%, 0%]`와 `[50%, 50%]`는 같은 그룹 점수입니다. 최소 일치율, 후보 다양성, 비선호 없는 후보 우선 정책은 이번 변경에 포함하지 않습니다.
- 개인·비회원·그룹은 점수순으로 최대 3개 후보를 반환합니다. 남은 메뉴가 적으면 3개 미만, 없으면 빈 목록입니다. 메뉴가 남아 있으면 0점 후보도 반환할 수 있습니다.

## 검증 근거와 API 진입점

- `RecommendationPreferenceBaselineTest`: 유형 정보가 없는 입력의 변경 전 50점·66.7점·100점 기준.
- `RecommendationScoreComparisonIntegrationTest`: 두 브랜치에서 같은 조건으로 실행하여 그룹 점수 3줄을 출력.
- `PersonalMenuRecommendationAlgorithmV1Test`: 회원 개인 `v1.2`의 모든 유형 OR 계산, 무이력 완전 충족 100점과 이력 결합.
- `RecommendationExclusivePreferenceTest`: 회원 개인 `v1.2`와 비회원·그룹 `v1.1`의 OR 적용 범위 구분, 불일치, 유형별 독립 계산, 그룹 비선호 감점.
- `PersonalRecommendationIntegrationTest`, `GuestRecommendationIntegrationTest`, `GroupIntegrationTest`: 실제 카테고리 유형 조회부터 후보 점수 반환·저장까지 검증.
- [개인·비회원 추천 API](../api/recommendation.md), [그룹 의사결정 API](../api/group.md).
